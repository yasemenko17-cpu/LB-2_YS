# Відповіді

1. Як слеш наприкінці proxy_pass впливає на шлях, який отримує бекенд?

Відповідь: Якщо в директиві proxy_pass немає слешу наприкінці (наприклад, proxy_pass [http://127.0.0.1:9000](http://127.0.0.1:9000)), Nginx передає шлях на бекенд повністю без змін (разом із префіксом location). Якщо ж слеш присутній (наприклад, proxy_pass [http://127.0.0.1:9000/](http://127.0.0.1:9000/)), Nginx замінює префікс поточного location на цей слеш (або новий шлях), відрізаючи збіжну частину URL.

2. Для чого у сертифікаті потрібне поле SAN?

Відповідь: Поле SAN (Subject Alternative Name) дозволяє вказати список додаткових доменних імен та IP-адрес, для яких дійсний цей сертифікат. Сучасні браузери та клієнти обов'язково перевіряють SAN, і якщо запитаний домен відсутній у цьому полі, з'єднання блокується через помилку безпеки (навіть якщо правильно заповнено поле CN).

3. Які заголовки передає ваш проксі і навіщо?

Відповідь: В конфігу для варіанта 23 передаються такі заголовки:
Host $host — передає оригінальне доменне ім'я запиту, щоб бебекнд знав, до якого саме сайту звертається клієнт.   
X-App-Name TechLife — кастомний заголовок із назвою програми, який вимагається за умовами 23-го варіанта для ідентифікації сервісу..
